# SEO configuration

The public production origin is configured with `VITE_SITE_URL` and currently defaults to:

```text
https://jewisheducationalresources.org
```

The frontend owns the page title, description, canonical URL, robots directive, Open Graph tags, Twitter card tags, and JSON-LD after hydration. The generated backend shell also injects the same public metadata before JavaScript runs, so crawlers and link unfurlers receive meaningful HTML on direct requests. The router applies a safe default after every SPA navigation; Home, Library, Category, and Resource views replace that default after their persisted content loads.

## Indexable pages

- `/`
- `/library`
- `/library/category/:slug` when no search or filter query is active
- `/resource/:slug`

Filtered/search states keep `noindex,follow` and canonicalize to the unfiltered parent page. This prevents duplicate catalog URLs from competing in search results.

## Never index

Authentication, account, admin, editor, download, and presentation-viewer routes use `noindex,nofollow,noarchive`. Protected file URLs are never placed in JSON-LD or the sitemap.

## Discovery

- `https://jewisheducationalresources.org/robots.txt` is served as plain text by the public SEO endpoint, with the checked-in Hosting asset as the build fallback.
- `https://jewisheducationalresources.org/sitemap.xml` is generated by the public backend endpoint and contains only published resources and public categories.
- The sitemap reads published resources in adapter pages, but emits only the canonical home, library, category, and resource URLs; filter and pagination query states are not sitemap entries.
- Firebase sends direct `/resource/:slug/download/:fileId` and `/resource/:slug/present/:fileId` requests to the SPA shell before the generic resource function rewrite, so those client routes can authenticate/render instead of returning a function 404.
- Submit the sitemap URL in Google Search Console after the Firebase deployment.

## Firebase console-only pending item

`www.jewisheducationalresources.org` is retained as a valid authorized/custom URL, but its Firebase Hosting custom-domain DNS verification and managed certificate must be confirmed in the Firebase console. Until the console shows the `www` certificate as active and the hostname serves the Hosting site over HTTPS, keep the canonical origin at `https://jewisheducationalresources.org`. This is an external DNS/certificate configuration task; it cannot be fixed by repository changes, and it does not require changing `JWT_SECRET` or `MIGRATION_SECRET`.

Before the next release, verify in Firebase Hosting that both the apex and `www` domains are attached to the intended site, DNS records are valid, and `www` returns the same robots, sitemap, and public metadata responses. Do not deploy while the managed certificate is pending or invalid.

## Content rules for editors

Use a specific material title, a one- or two-sentence description, an accurate category, grade/age information, keywords that appear in the material, and a real cover image with meaningful alt text. Do not add promotional claims, ratings, FAQs, or authors that are not supported by the saved content.
